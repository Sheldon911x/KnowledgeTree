mini-harness：第一个可归因的对照实验 + Python 扫盲第一课

核心收获一句话：模型动嘴（读上下文、生成文本），harness 动手（执行、拼接、捕获、回填、再调用）——core.py 就是 harness，模型只是它调用的外部服务。

01实验矩阵：四格完整闭合

第一个严格遵循"单变量原则"的 harness 对照实验。变量只有两个：工具描述是否带正反示例、read_file 是否带路径归一化容错。

#描述强化归一化容错结果归因
1❌ 模糊描述❌失败：模型传 sandbox/a.txt，还转述了污染路径模型犯错，无人兜底
2✅✅成功混合变量，无法归因（反面教材）
3✅❌ 注释掉成功行为成功：模型压根没犯错
4❌ 模糊描述✅成功：介入日志首次实战打出兜底成功：模型犯了错，被静默修复
严谨性注：每格 n=1，但跨格互证——模糊描述下模型 2/2 犯同一错，强化描述下 2/2 传对。错误模式稳定，结论可信。想更严格可每格补跑到 3 次。

02核心概念：行为成功 vs 兜底成功

两种"成功"看着一样，本质完全不同。这是防御性 harness 的全部含义。

行为成功（描述强化）兜底成功（归一化）
本质模型没犯错模型犯了错，被 harness 静默修复
可迁移性✅ 好习惯能迁移到别的工具❌ 只防住这一个工具的这一类错
代价提示词更长，且永不保证 100%每个工具都要写容错代码
工程结论该做更该做——它是保险丝
双保险原则：描述强化降低犯错概率，归一化兜住漏网之鱼。正式配置 = 两者常驻。
可观测性：正确答案 ≠ 健康过程。格 4 若没有那行介入日志 [harness] 路径归一化介入: sandbox/a.txt -> a.txt，从输出完全看不出模型犯了错。真实 harness 全靠日志发现"系统看着健康，其实错误率在爬升"。
双刃剑：归一化让错误对模型"隐身"——上下文干净了，但模型永远不知道自己习惯有问题。成熟策略：可自动修复的错误静默兜底 + 记日志；不可修复的才回填给模型。

03Python 第一课：等号不是"相等"，是"装进盒子"

编程的 = 是赋值动作：先算右边的值，再装进左边的盒子。同一行里两个 path 不是同一时刻的东西。

path = path.replace("\\", "/")
       └──────┬──────┘
   第①步：用 path 盒子里的【旧值】算出新字符串
└─┬─┘
  第②步：新字符串装回 path 盒子，旧值被顶掉、丢弃
符号读作干什么例子
=赋值把右边装进左边（动作）raw = path
==等于问"一样吗"，答 True/Falsepath == "a.txt"
!=不等于问"不一样吗"if path != raw:
为什么需要 raw = path 提前拍照：旧值一旦被顶掉就永远消失。没有存档，就没法做"介入检测"（path != raw 时才打日志）。

04读懂代码的三板斧

遇到陌生代码的固定打法，今天全部实战过。

① 翻译方法名方法名就是英语单词本义：replace=替换、startswith=以…开头、len=长度、read=读、print=打印。读懂代码第一步是翻译。
② 盯盒子的进出每个变量是一个贴标签的盒子。赋值=复制内容进盒子；旧值没存档就永远消失。
③ 确认执行顺序先归一化切前缀，后拼接路径——顺序反了就会拼出 sandbox/sandbox/a.txt。
对象类型决定工具箱replace 是字符串的工具，read 是文件对象的工具。盒子装什么类型，就带什么工具。工具清单不用背，用阅读量养出"地图感"。
知识点一句话记住
反斜杠 \Windows 路径分隔符 + 字符串转义符（ 换行）；想表示货真价实的反斜杠要写两个 \\
f-string字符串前加 f 是总开关；每个 {} 在打印瞬间填入当前值；{} 里还能放表达式如 {len(path)}
变量命名prefix 就叫"前缀"，因为装的就是要检查的开头一截。起名用有词义的英语，让代码像文章一样能读
removeprefix"直接删前缀"的专用武器（Python 3.9+）；切片是通用武器。专用武器更好读，通用武器什么都能干
容错的本质Python 对"前缀"一无所知——候选前缀是人工枚举的。harness 容错层是事故的纪念碑：你只能防住你预见到的错误

05模型动嘴，harness 动手：首次失败事件七步还原

Agent 系统的根本分工。标出每一步的责任人，就不会把拼接、回填记到模型头上。

步骤责任人干了什么
1用户命令行执行 python core.py
2harness把任务文本、系统提示、工具清单组装进 messages，发给模型
3模型读完上下文，在回复里写下一句话："我要调 read_file，参数是 sandbox/a.txt"——只生成文本，什么都没拼接
4harness取出参数，执行拼接 "./sandbox/" + "sandbox/a.txt" → 打开文件 → 不存在，异常
5harness捕获异常，错误文本作为 tool 消息回填 messages
6harness带着更新后的 messages 再次调用模型
7模型读到错误，没自我纠正，输出最终回答（转述了污染路径）
core.py 就是 harness。模型是住在 localhost:11434 里的 qwen2.5:3b；core.py 里的一切——组装、执行、拼接、捕获、回填、循环——全是 harness 的职责。tool_call 本质也是模型生成的一段特殊格式文本，"模型调工具"其实是"harness 读到模型的话后替它执行"。
